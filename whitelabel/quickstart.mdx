In about twenty minutes you will have a client account linked to yours through the HEVN sign-in window, holding testnet USDC, with one payout its holder approved and HEVN settled on chain. Ten steps, all of them in the sandbox.

## Before you start

- **Create a sandbox account in a browser.** Sign up at
  [`https://sandbox.gethevn.com`](https://sandbox.gethevn.com) with your work email. Sandbox and
  production are separate accounts; nothing you do here touches real money.
- **Create a developer key, in the same browser.** Open **Settings → Partner program → Developer** and create one.
  You set one thing that can never be changed afterwards: the **IP allowlist**, which for this
  quickstart is the egress address of the machine you will run it from. Every later call is
  re-checked against it — a request from an address you did not list is a `403` however correct the
  key and the signature are.
- **Allow your local site in the sign-in window.** On the same tab, in the **Sign-in window** card,
  add `http://localhost:8080` under **Allowed sites** and save. Give the window a title while you are
  there; it is what your test customer will see.
- **Have a second Google account ready.** It plays your customer. It must not have a HEVN sandbox
  account of its own: an existing account answers `already_registered` and can never be linked.
- **Save the private key into your environment.** The browser shows it once. Write it to
  `$HEVN_KEY_PEM` with mode `0600`; HEVN never holds it and cannot show it again. Walk-through:
  [Developer key](/whitelabel/developer-key).
- **Set the environment and install two dependencies.** Everything after that is code.

## Ten steps

<Steps>
  <Step title="Log in">
    Two calls: `POST /dapi/v1/auth/challenge` returns a payload built by HEVN, and
    `POST /dapi/v1/auth/token` exchanges your signature over it for a session. The helpers this uses —
    `load_key`, `public_key_b64`, `sign_bytes`, `sign_payload` — are on
    [Developer key](/whitelabel/developer-key) and [Signing](/whitelabel/signing).

    <LoginSnippet />

    ```json Response
    {
      "accessToken": "eyJhbGciOiJFUzI1NiIsInR5cCI6IkpXVCJ9…",
      "refreshToken": "eyJhbGciOiJFUzI1NiIsInR5cCI6IkpXVCJ9…",
      "expiresIn": 3600,
      "userId": "cl_9f2c1ab84d7e4f1fa3c65b0e7d9a2c41"
    }
    ```

    Keep both: `export HEVN_ACCESS_TOKEN=…` and `export HEVN_USER_ID=cl_9f2c…`.

    The `hevn` / `api` client, `key` and `poll_until` in every tab below are
    [the reference client](/whitelabel/reference/client) — copy it once and the rest of this page
    is three lines a step.
  </Step>

  <Step title="Serve a page that opens the sign-in window">
    The window is opened by your page and answers to your callback page. For this quickstart both are
    static files. Save them in an empty folder and serve it on the origin you allowed:

    ```html index.html
    <!doctype html>
    <meta charset="utf-8">
    <title>HEVN quickstart</title>
    <input id="url" placeholder="Paste a session url" size="90">
    <button id="open">Open HEVN</button>
    <pre id="out"></pre>
    <script>
      const out = document.getElementById("out");
      const channel = new BroadcastChannel("hevn-connect");
      channel.onmessage = ({ data }) => { out.textContent = JSON.stringify(data.result, null, 2); };
      document.getElementById("open").onclick = () => {
        window.open(document.getElementById("url").value, "hevn-connect", "popup,width=460,height=720");
      };
    </script>
    ```

    ```html callback.html
    <!doctype html>
    <meta charset="utf-8">
    <title>Signing in…</title>
    <script>
      const result = Object.fromEntries(new URLSearchParams(location.search));
      if (result.state) {
        const channel = new BroadcastChannel("hevn-connect");
        channel.postMessage({ state: result.state, result });
        channel.close();
        window.close();
      }
    </script>
    ```

    ```bash
    python3 -m http.server 8080
    ```

    Open `http://localhost:8080` in a browser. The popup opens straight from the click, which is what
    keeps the browser from blocking it. A real integration fetches the session URL from its own server
    inside that click instead of having you paste it — [Sign in with HEVN](/whitelabel/sign-in-with-hevn)
    has that version, and the cookie check this quickstart skips.
  </Step>

  <Step title="Create a link session">
    The session is about your own account, so it carries **no** `X-Hevn-Account`.

    <CodeGroup>

    ```bash cURL
    curl -s -X POST "$HEVN_API/connect/sessions" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" -H "Content-Type: application/json" \
      -d '{"action":"link","redirectUri":"http://localhost:8080/callback.html"}' | jq -r .url
    ```

    ```python Python
    session = hevn.post("/connect/sessions", {
        "action": "link", "redirectUri": "http://localhost:8080/callback.html",
    })
    print(session["url"])
    ```

    ```javascript Node
    const session = await hevn.post("/connect/sessions", {
      action: "link", redirectUri: "http://localhost:8080/callback.html",
    });
    console.log(session.url);
    ```

    ```go Go
    session, err := api.Post("/connect/sessions", hevn.Body{
    	"action": "link", "redirectUri": "http://localhost:8080/callback.html",
    })
    fmt.Println(session.Str("url"))
    ```

    </CodeGroup>

    ```json Response
    { "url": "https://sandbox.gethevn.com/connect?session=eyJ…", "state": "pQ8v2Zr0…", "expiresAt": "2026-09-17T10:14:11Z" }
    ```

    The URL works for about ten minutes. `403 redirect_uri_not_allowed` means `http://localhost:8080`
    is not saved under **Allowed sites**. `403 client_creation_not_enabled` means your account is not
    an active integrator yet; ask HEVN before you write any more code — see
    [Going live](/whitelabel/going-live#what-hevn-must-enable).
  </Step>

  <Step title="Sign in as your customer">
    Paste the URL into the page and click **Open HEVN**. In the popup, sign in with the second Google
    account and choose **Allow**. The popup closes and the page shows what came back:

    ```json
    { "code": "eyJhbGciOiJFUzI1NiIs…", "state": "pQ8v2Zr0…" }
    ```

    `state` is the one `POST /connect/sessions` answered. The code lives for five minutes.
  </Step>

  <Step title="Exchange the code for a client">
    <CodeGroup>

    ```bash cURL
    curl -s -X POST "$HEVN_API/clients/link" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" -H "Content-Type: application/json" \
      -d '{"code":"eyJhbGciOiJFUzI1NiIs…"}' | jq '{id, status, baseSmartWallet}'
    ```

    ```python Python
    client = hevn.post("/clients/link", {"code": code})
    northwind = hevn.acting_as(client["id"])
    ready = poll_until(lambda: northwind.get("/client"),
                       lambda seen: seen["status"] != "provisioning")
    ```

    ```javascript Node
    const client = await hevn.post("/clients/link", { code });
    const northwind = hevn.actingAs(client.id);
    const ready = await pollUntil(() => northwind.get("/client"),
      (seen) => seen.status !== "provisioning");
    ```

    ```go Go
    client, err := api.Post("/clients/link", hevn.Body{"code": code})
    northwind := api.ActingAs(client.Str("id"))
    ready, err := hevn.PollUntil(
    	func() (hevn.Payload, error) { return northwind.Get("/client") },
    	func(seen hevn.Payload) bool { return seen.Str("status") != "provisioning" },
    	2*time.Minute,
    )
    ```

    </CodeGroup>

    ```json Response
    { "id": "cl_7YQ2Kf3mN8", "status": "ready", "baseSmartWallet": "0x2f1c9d0b8a7e6532d41ac9f0b3e27d5581a4c6f9" }
    ```

    Keep the id: `export HEVN_CLIENT_ID=cl_7YQ2Kf3mN8`. If it says `provisioning`, read
    `GET /dapi/v1/client` with the id in `X-Hevn-Account` every two seconds until it is `ready`.
  </Step>

  <Step title="Fund the client's wallet">
    The sandbox mints emulated money. Without `bankId` this is a token transfer straight to the
    client's wallet; the `X-Hevn-Account` header that `northwind` carries is what makes the call act
    for the client.

    <CodeGroup>

    ```bash cURL
    curl -X POST "$HEVN_API/sandbox/deposits" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
      -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
      -H "Idempotency-Key: quickstart-deposit-1" \
      -H "Content-Type: application/json" -d '{"amount":"5.00","token":"USDC"}'
    ```

    ```python Python
    credit = northwind.post("/sandbox/deposits", {"amount": "5.00", "token": "USDC"},
                            idempotency_key="quickstart-deposit-1")
    ```

    ```javascript Node
    const credit = await northwind.post("/sandbox/deposits",
      { amount: "5.00", token: "USDC" },
      { idempotencyKey: "quickstart-deposit-1" });
    ```

    ```go Go
    credit, err := northwind.Post("/sandbox/deposits", hevn.Body{"amount": "5.00", "token": "USDC"},
    	hevn.IdempotencyKey("quickstart-deposit-1"))
    ```

    </CodeGroup>

    A `200` means the tokens landed; a `202` means they are on their way and the same request,
    with the same key, is safe to repeat. The faucet sends at most `5` per call, and only to a
    wallet that holds less than `1` of that token ([Sandbox limits](/whitelabel/sandbox#limits)).
  </Step>

  <Step title="Read the balance you just created">
    `/client/balance` names no client in its path either: the header picks the account, and leaving
    it out is a `422` for a missing header rather than a read of your own wallet.

    <CodeGroup>

    ```bash cURL
    curl -s "$HEVN_API/client/balance" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
      -H "X-Hevn-Account: $HEVN_CLIENT_ID" | jq
    ```

    ```python Python
    balance = northwind.get("/client/balance")
    ```

    ```javascript Node
    const balance = await northwind.get("/client/balance");
    ```

    ```go Go
    balance, err := northwind.Get("/client/balance")
    ```

    </CodeGroup>

    ```json Response
    {
      "clientId": "cl_7YQ2Kf3mN8",
      "baseSmartWallet": "0x2f1c9d0b8a7e6532d41ac9f0b3e27d5581a4c6f9",
      "accounts": [{ "account": "USDC", "balance": "5.000000", "usdValue": "5.00" }],
      "totalUsd": "5.00"
    }
    ```

    That balance is read from Base Sepolia, not from a HEVN table.
  </Step>

  <Step title="Save a contact and book a payout">
    Pay the money to an address you control: your own account's wallet. Read it with the same
    balance route, acting as yourself — the `userId` from step 1 goes in `X-Hevn-Account`, because
    that header is the only thing that selects an account on `/client*`. Then book `1.00` to it.

    <CodeGroup>

    ```bash cURL
    export HEVN_OWN_WALLET=$(curl -s "$HEVN_API/client/balance" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
      -H "X-Hevn-Account: $HEVN_USER_ID" | jq -r .baseSmartWallet)

    export HEVN_CONTACT_ID=$(curl -s -X POST "$HEVN_API/contacts" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
      -H "Content-Type: application/json" \
      -d "{\"name\":\"Treasury\",\"crypto\":{\"chain\":\"base\",\"token\":\"USDC\",\"address\":\"$HEVN_OWN_WALLET\"}}" | jq -r .id)

    curl -s -X POST "$HEVN_API/payouts" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
      -H "Idempotency-Key: quickstart-payout-1" -H "Content-Type: application/json" \
      -d "{\"contactId\":\"$HEVN_CONTACT_ID\",\"amount\":\"1.00\"}"
    ```

    ```python Python
    own_wallet = hevn.acting_as(user_id).get("/client/balance")["baseSmartWallet"]
    contact = northwind.post("/contacts", {
        "name": "Treasury",
        "crypto": {"chain": "base", "token": "USDC", "address": own_wallet},
    })
    payout = northwind.post("/payouts", {"contactId": contact["id"], "amount": "1.00"},
                            idempotency_key="quickstart-payout-1")
    ```

    ```javascript Node
    const { baseSmartWallet: ownWallet } = await hevn.actingAs(userId).get("/client/balance");
    const contact = await northwind.post("/contacts", {
      name: "Treasury",
      crypto: { chain: "base", token: "USDC", address: ownWallet },
    });
    const payout = await northwind.post("/payouts", { contactId: contact.id, amount: "1.00" },
      { idempotencyKey: "quickstart-payout-1" });
    ```

    ```go Go
    own, err := api.ActingAs(userID).Get("/client/balance")
    contact, err := northwind.Post("/contacts", hevn.Body{
    	"name":   "Treasury",
    	"crypto": hevn.Body{"chain": "base", "token": "USDC", "address": own.Str("baseSmartWallet")},
    })
    payout, err := northwind.Post("/payouts", hevn.Body{"contactId": contact.Str("id"), "amount": "1.00"},
    	hevn.IdempotencyKey("quickstart-payout-1"))
    ```

    </CodeGroup>

    ```json Response
    {
      "id": "po_6d21…",
      "kind": "onchain",
      "status": "awaitingSignature",
      "idempotencyKey": "quickstart-payout-1",
      "quote": { "fromAmount": "1.00", "fromCurrency": "USDC", "toAmount": "1.00", "toCurrency": "USDC" },
      "authorization": "client",
      "contact": { "contactId": "ct_3K9…", "name": "Treasury",
                   "address": "0x8f3bd1c7a0e94f25b6d1c83a5e07f4b219ad6e80",
                   "chainId": "base", "token": "USDC" }
    }
    ```

    `authorization: "client"` and no `approval`: this is the client's money, so its holder signs it,
    not your key. Keep the id: `export HEVN_PAYOUT_ID=po_6d21…`. `quickstart-payout-1` names this
    payment — re-run the call with the same key and you replay it; change the key and you book twice.
  </Step>

  <Step title="Approve it in the sign-in window">
    Create a `sign` session for the payout, paste its URL into the page and click **Open HEVN** again.

    <CodeGroup>

    ```bash cURL
    curl -s -X POST "$HEVN_API/connect/sessions" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" -H "Content-Type: application/json" \
      -d "{\"action\":\"sign\",\"payoutId\":\"$HEVN_PAYOUT_ID\",\"redirectUri\":\"http://localhost:8080/callback.html\"}" \
      | jq -r .url
    ```

    ```python Python
    session = hevn.post("/connect/sessions", {
        "action": "sign", "payoutId": payout["id"],
        "redirectUri": "http://localhost:8080/callback.html",
    })
    ```

    ```javascript Node
    const session = await hevn.post("/connect/sessions", {
      action: "sign", payoutId: payout.id,
      redirectUri: "http://localhost:8080/callback.html",
    });
    ```

    ```go Go
    session, err := api.Post("/connect/sessions", hevn.Body{
    	"action": "sign", "payoutId": payout.Str("id"),
    	"redirectUri": "http://localhost:8080/callback.html",
    })
    ```

    </CodeGroup>

    Sign in with the same second Google account. The window shows `1.00 USDC`, the contact `Treasury`
    and your title, and the holder's wallet signs the debit. The page then shows:

    ```json
    { "status": "submitted", "payout": "po_6d21…", "reference": "0x…", "state": "…" }
    ```
  </Step>

  <Step title="Read the payout and the ledger">
    The redirect said `submitted`. The payout read is the record:

    <CodeGroup>

    ```bash cURL
    curl -s "$HEVN_API/payouts/$HEVN_PAYOUT_ID" \
      -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
      | jq '{status, transactionHash}'
    ```

    ```python Python
    done = poll_until(lambda: northwind.get(f"/payouts/{payout['id']}"),
                      lambda seen: seen["status"] not in ("awaitingSignature", "submitted"))
    rows = northwind.get("/transactions", {"limit": 5})["items"]
    ```

    ```javascript Node
    const done = await pollUntil(() => northwind.get(`/payouts/${payout.id}`),
      (seen) => !["awaitingSignature", "submitted"].includes(seen.status));
    const { items: rows } = await northwind.get("/transactions", { limit: 5 });
    ```

    ```go Go
    done, err := hevn.PollUntil(
    	func() (hevn.Payload, error) { return northwind.Get("/payouts/" + payout.Str("id")) },
    	func(seen hevn.Payload) bool { s := seen.Str("status"); return s != "awaitingSignature" && s != "submitted" },
    	2*time.Minute,
    )
    page, err := northwind.Get("/transactions", hevn.Query{"limit": "5"})
    ```

    </CodeGroup>

    ```json Response
    { "status": "settled", "transactionHash": "0x3a77…" }
    ```

    The ledger row carries its amounts as two sides — `from` is what left the source, `to` is what
    arrived — rather than a single `amount`. On this payout both are `1.000000 USDC`, and the same
    1 USDC is now in your own account's balance: read it with the balance call from step 7, with
    `$HEVN_USER_ID` in `X-Hevn-Account`.
  </Step>
</Steps>

## What just happened

- **Your customer owns the account.** They created it in the sign-in window with their own Google
  sign-in, and allowed your product to act on it. You got a `cl_…` id, never their credentials.
- **Your key logged you in; it never touched their money.** The payout was booked by you and signed by
  the holder's own wallet. See [Accounts and control](/whitelabel/accounts-and-control).
- **The money is real testnet money.** It moved on Base Sepolia; `transactionHash` is on chain.
- **Every constant came out of an earlier response.** Client id, wallet address, contact id, payout
  id — nothing was invented.
- **One key was yours to choose:** the `Idempotency-Key`. It names the payment, so a retry is the
  same payment. See [Conventions](/whitelabel/conventions#idempotency-key).

## What this quickstart did not do

It skipped the server half of the sign-in: binding the session's `state` to the browser and keeping
the client id in your own session. Do that before anything else — [Sign in with HEVN](/whitelabel/sign-in-with-hevn).

It never touched fiat either. Getting the client its own account details, and paying a bank account with
a currency conversion, needs a client the partner has approved: the KYB document filled and its rail open.
That is the next piece of work — [Onboard a client](/whitelabel/onboarding), then
[Virtual accounts](/whitelabel/virtual-accounts) and [Payouts](/whitelabel/payouts).
