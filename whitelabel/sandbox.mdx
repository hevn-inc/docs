The sandbox is the production API running against one emulated partner bank on Base Sepolia. Fund a client with `POST /dapi/v1/sandbox/deposits`, drive KYB, payins and payouts with the routes below, then [go live](#go-live).

<EnvSnippet />

`X-Hevn-Account` selects the client ([Acting as a client](/whitelabel/authentication#acting-as-a-client)).

Clients link through [Sign in with HEVN](/whitelabel/sign-in-with-hevn) with a real sign-in. Each test client needs a Google account or email address with no HEVN sandbox account.

Add your test origin, for example `http://localhost:<port>`, under **Allowed sites** in the sandbox app.

## What HEVN must enable

HEVN grants these in both environments. No API call sets them.

| Grant | Without it | When to ask |
| --- | --- | --- |
| An active integrator profile that may link clients | `403 client_creation_not_enabled` on `POST /dapi/v1/connect/sessions` and `POST /dapi/v1/clients/link`. `403 account_forbidden` on calls that act for an existing client. | Before you write production code. |
| Escrow operation | Escrow actions are refused. | When funds must be locked on chain between your customers. |
| The rails you need | `403 rail_not_available` on `POST /dapi/v1/banks` | Name the currencies and countries you sell into. Availability is set per integrator and per client. |

## Environment

| Area | Sandbox |
| --- | --- |
| Chain | Wallets, balances, signatures and transaction hashes are real. Tokens are testnet USDC and EURC. |
| Partner bank | One emulator for all rails. Account details are checksum-valid: `SBOX…` BICs, DE, AE and GB IBANs, ABA routing numbers, a PIX key, an 18-digit SPEI number. |
| FX | Fixed rates, for example USD 1, EUR 1.08, GBP 1.27 and AED 0.2723. USDC is pegged to USD, EURC to EUR. |
| Verification | No registry or document check. Made-up companies, people and documents pass once the KYB document is `ready: true` and you [approve the application](#decide-a-kyb-application). |
| Background work | Off. Each call writes its rows before it returns. |
| Swaps | `POST /dapi/v1/swaps` and `POST /dapi/v1/swaps/preview` return `422 swap_route_unavailable`. The sandbox issues no dollar balance held at the partner bank. |
| Partner-issued cards, cross-chain routing | Disabled. Not part of the whitelabel API. |
| Source IP | Checked against the key's [allowlist](/whitelabel/authentication#the-ip-allowlist). An unlisted address gets `403` on all routes. |

## Read the faucet account

`GET /dapi/v1/sandbox/treasury` returns the shared testnet faucet account that pays emulated credits and receives the funds of emulated payouts.

<CodeGroup>

```bash cURL
curl -s "$HEVN_API/sandbox/treasury" -H "Authorization: Bearer $HEVN_ACCESS_TOKEN"
```

```python Python
treasury = hevn.get("/sandbox/treasury")
```

```javascript Node
const treasury = await hevn.get("/sandbox/treasury");
```

```go Go
treasury, err := api.Get("/sandbox/treasury")
```

</CodeGroup>

```json Response: 200
{ "chainId": 84532, "address": "0x7d4E5E29e6d40735D4f9bB74a0234383068f8A21",
  "gasBalance": "0.0412", "maxCredit": "1",
  "balances": [ { "token": "USDC", "tokenAddress": "0x036CbD…", "balance": "842.51" }, … ] }
```

When the faucet account is out of tokens or gas, credits return `503 provider_unavailable` with `details.treasuryAddress` and `details.token`.

## Mint money

`POST /dapi/v1/sandbox/deposits` credits a client. With `bankId` it books an unquoted payin to that virtual account at the fixed rate. Without it, the faucet sends `token` to the client's wallet, within the faucet [limits](#limits). Fields: [Emulate an incoming deposit](/api-reference/sandbox/emulate-an-incoming-deposit:-an-account-transfer-with-bankid-a-token-transfer-without).

<CodeGroup>
```bash cURL
curl -s -X POST "$HEVN_API/sandbox/deposits" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
  -H "Idempotency-Key: fund-client-001" \
  -H "Content-Type: application/json" \
  -d '{"amount":"5.00","token":"USDC"}'
```

```python Python
client = hevn.acting_as(CLIENT_ID)
credit = client.post("/sandbox/deposits", {"amount": "5.00", "token": "USDC"},
                     idempotency_key="fund-client-001")
```

```javascript Node
const client = hevn.actingAs(clientId);
const credit = await client.post("/sandbox/deposits",
  { amount: "5.00", token: "USDC" },
  { idempotencyKey: "fund-client-001" });
```

```go Go
client := api.ActingAs(clientID)
credit, err := client.Post("/sandbox/deposits", hevn.Body{"amount": "5.00", "token": "USDC"},
	hevn.IdempotencyKey("fund-client-001"))
```
</CodeGroup>

```json Response: 200
{ "depositId": "sbx_cd_1b8e0f7a2c", "status": "settled",
  "token": "USDC", "amount": "5.000000", "currency": "USDC",
  "idempotencyKey": "fund-client-001",
  "credited": "5.000000", "txHash": "0x08fa…", "transactionId": "txn_9e4…" }
```

`202` means the faucet transfer is unconfirmed. Repeat the same request until `status` is `settled`. The amount is credited once.

Identical requests without an [`Idempotency-Key`](/whitelabel/conventions#idempotency-key) replay the first credit at any interval. Send a new key to credit the same amount again.

## Decide a KYB application

A completed KYB submission stays `pending` until you call `POST /dapi/v1/sandbox/kyb/status`. The call sets the status of the client's latest application.

<CodeGroup>

```bash cURL
curl -s -X POST "$HEVN_API/sandbox/kyb/status" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
  -H "Content-Type: application/json" \
  -d '{"status":"rfi","comment":"The proof of address for Jane Doe is older than three months."}'
```

```python Python
kyb = client.post("/sandbox/kyb/status", {"status": "approved"})
```

```javascript Node
const kyb = await client.post("/sandbox/kyb/status", { status: "approved" });
```

```go Go
kyb, err := client.Post("/sandbox/kyb/status", hevn.Body{"status": "approved"})
```

</CodeGroup>

The statuses, what each needs and the refusals are on [Decide the client's latest KYB application](/api-reference/sandbox/decide-the-clients-latest-kyb-application-as-the-compliance-reviewer-would). After `rfi`, [answer the RFI](/whitelabel/clients#answer-an-rfi) and complete the submission again, then decide the new application. After `rejected`, a new attempt needs a new submission. For an individual client, `approved` sets `verifiedAt`.

## Settle a payin

`POST /dapi/v1/sandbox/payins/{payinId}/complete` emulates the payer's bank transfer for a quoted payin.

<CodeGroup>

```bash cURL
curl -s -X POST "$HEVN_API/sandbox/payins/pi_2b7f14c0a9/complete" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
  -H "Content-Type: application/json" \
  -d '{"remitter":"ACME GmbH"}'
```

```python Python
settled = client.post(f"/sandbox/payins/{payin['id']}/complete", {"remitter": "ACME GmbH"})
```

```javascript Node
const settled = await client.post(`/sandbox/payins/${payin.id}/complete`,
  { remitter: "ACME GmbH" });
```

```go Go
settled, err := client.Post("/sandbox/payins/"+payin.Str("id")+"/complete",
	hevn.Body{"remitter": "ACME GmbH"})
```

</CodeGroup>

Open the payin with `POST /dapi/v1/payins/{payinId}/instructions` first. The body and refusals are on [Emulate the arrival of the funds](/api-reference/sandbox/emulate-the-arrival-of-the-funds-a-pay-in-is-waiting-for).

## Move a payout

Book and sign a payout as in production, then set its status with `POST /dapi/v1/sandbox/payouts/{payoutId}/status`.

<CodeGroup>
```bash cURL
curl -s -X POST "$HEVN_API/sandbox/payouts/po_4c8a13d7f2/status" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
  -H "Content-Type: application/json" \
  -d '{"status":"settled"}'
```

```python Python
moved = client.post(f"/sandbox/payouts/{payout['id']}/status", {"status": "settled"})
```

```javascript Node
const moved = await client.post(`/sandbox/payouts/${payout.id}/status`, { status: "settled" });
```

```go Go
moved, err := client.Post("/sandbox/payouts/"+payout.Str("id")+"/status",
	hevn.Body{"status": "settled"})
```
</CodeGroup>

The statuses, which need a funded payout and the refusals are on [Move an emulated outgoing transfer](/api-reference/sandbox/move-an-emulated-outgoing-transfer-to-its-next-reported-status). A `settled` payout's row in `GET /dapi/v1/transactions` has `status: "success"`. `failed` does not return the debited amount.

A return is matched to a refunded payout by amount, within `0.20`. Keep test payouts more than `0.20` apart.

## Limits

Production has none of these limits.

| Limit | Value | Refusal |
| --- | --- | --- |
| One payout | At most `1` of the debited account. A bank payout starts at `0.10` and costs the rail's `feeBps`, with no fixed fee. | `422 sandbox_amount_limit_exceeded`. `400 invalid_request` below the minimum. |
| One escrow | `maxAmount` at most `1`. Its actions cannot exceed it. | `422 sandbox_amount_limit_exceeded` |
| One payin credit (with `bankId`, or a completed payin) | `0.10` to `1` (`maxCredit`) of the credited token | `422 amount_below_minimum`, `422 sandbox_amount_limit_exceeded` |
| One faucet credit (without `bankId`) | `0.10` to `5`, while the wallet holds less than `1` of that token | `422 amount_below_minimum`, `422 sandbox_amount_limit_exceeded`, `409 sandbox_faucet_balance_too_high` |
| Calls to `/sandbox/deposits`, `/sandbox/payins/{payinId}/complete` and `/sandbox/payouts/{payoutId}/status` | 60 per account per hour | `429 rate_limited` |

`sandbox_amount_limit_exceeded` returns `details.operation` (`payout`, `escrow`, `payin` or `faucet`) and `details.maximum`, plus `details.amount` and `details.currency` for a payout or escrow. `sandbox_faucet_balance_too_high` returns `details.balance`, `threshold` and `token`.

## Go live

Production has the same routes, bodies and error codes as the sandbox, with partner banks in place of the emulator. Ask HEVN to [enable your integrator account](#what-hevn-must-enable), then create a production developer key.

### Re-create per environment

| Object | In production |
| --- | --- |
| Developer key | Create one in the production app (`https://app.gethevn.com`) with your production egress addresses. The [allowlist](/whitelabel/authentication#the-ip-allowlist) cannot be edited, so list all calling hosts first. |
| Sign-in window | Add your production callback origins under **Allowed sites**. An unlisted `redirectUri` returns `403 redirect_uri_not_allowed`. Ask HEVN to brand the production window. Check that you [bind `state` to the browser](/whitelabel/sign-in-with-hevn#3-bind-the-session-to-this-browser). |
| Clients | A sandbox `cl_…` does not exist in production, and neither do its KYB, virtual accounts, contacts or escrow deals. Your customers link again. |
| Tokens | Access and refresh tokens are valid in one environment. |
| Virtual accounts | Product codes are the same. The products a client can request and the rail behind each differ. Read `GET /dapi/v1/banks` per client and do not store `rail`. |
| Idempotency keys | Scoped to your account and the environment. |

A key used against the other environment's host fails at login with `401 invalid_credentials`. The response does not name the environment, so check `HEVN_API` first.

### Timing

In production, the steps you trigger yourself in the sandbox wait on a reviewer or the partner bank. Poll as described in [Status codes](/whitelabel/conventions#status-codes).

| Step | Sandbox | Production |
| --- | --- | --- |
| KYB decision | You [decide the application](#decide-a-kyb-application). | A review. Poll `GET /dapi/v1/client/kyb` and handle `rfi`. |
| Virtual account | `active` with account details once no blocker remains, with no review. | `preparing` until the partner bank publishes the account details. Poll `GET /dapi/v1/banks`. |
| Payin and payout settlement | You [settle the payin](#settle-a-payin) and [move the payout](#move-a-payout). | Timing is set by the payer's bank and the partner bank. A `settled` payout is accepted and debited. Delivery can come later. |

### Production refusals

Production returns these for causes the emulator does not have.

| Signal | Cause | Action |
| --- | --- | --- |
| `422 contact_payment_details_invalid` | The receiving bank does not recognise the beneficiary, usually the name. | Correct the contact with `PATCH /dapi/v1/contacts/{contactId}` and book again. |
| A virtual account stays `preparing` | The partner bank is reviewing it. | Read `blockers[]` on `GET /dapi/v1/banks/{product}`. If it is empty, wait. |
| `422 amount_below_minimum`, `422 amount_above_maximum` | Rail limits replace the sandbox minimum of `0.10`. | Change the amount. |
| `attention: {"kind": "rfi"}` on a payout | The partner bank holds the payout until a question is answered. | Answer the question. Signing again does not release the payout. |
| `503 provider_unavailable` | The partner bank is unavailable. | Retry with backoff. Do not book again. |
| `429 rate_limited` | A [rate limit](/whitelabel/conventions#rate-limits) was reached. The counters are enforced in production. | Wait for `Retry-After`. |

Also handle the sign-in window results `access_denied`, `already_registered`, `already_linked` and `expired`, and the [funding codes](/whitelabel/reference/errors#funding-a-payment) for payouts from your integrator account.

### Checklist

<Steps>
  <Step title="Switch the host">
    Set `HEVN_API` to `https://api.hevn.finance/dapi/v1` and load the production key.
  </Step>
  <Step title="Remove sandbox calls">
    `/dapi/v1/sandbox/*` returns `404` in production. Poll for each state in [Timing](#timing).
  </Step>
  <Step title="Handle 429, 401 and 5xx">
    Handle `429`, `401` and `5xx` as in [Errors](/whitelabel/reference/errors). Log `X-Request-ID` and include it in support requests.
  </Step>
  <Step title="Rehearse key rotation">
    Create a second key whose allowlist covers your hosts. Log in with it and book a payout from your integrator account with its `publicKey`, then delete the old key ([Rotate a key](/whitelabel/authentication#rotate-a-key)).
  </Step>
  <Step title="Run one production payment">
    A payout debits the client's wallet and an escrow refund debits yours, so fund both. Link one client, pay a small amount to an account you control and reconcile it from `GET /dapi/v1/transactions`.
  </Step>
</Steps>
