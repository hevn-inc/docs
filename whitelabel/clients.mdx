title: "Clients and verification"
description: "Read and update a linked client, then write, submit and track a business client's KYB document."

A client is your customer's HEVN account, linked to your integrator account through [Sign in with HEVN](/whitelabel/sign-in-with-hevn). Read it with `GET /dapi/v1/client`, then verify a business client with `PUT /dapi/v1/client/kyb`.

`POST /dapi/v1/clients/link` returns the `cl_…` id. Send it as `X-Hevn-Account` to read the client with `GET /dapi/v1/client`.

```json POST /dapi/v1/clients/link 200
{
  "id": "cl_7YQ2Kf3mN8",
  "status": "ready",
  "email": "ops@northwind.example",
  "baseSmartWallet": "0x2f1c9a3b7e5d41c8a06f2d9b4e7c15839af0d6b2",
  "kybStatus": "notStarted",
  "createdAt": "2026-09-17T10:04:11Z",
  "pollUrl": "/dapi/v1/client"
}
```

The fields are described on [Connect an existing account](/api-reference/accounts/connect-an-existing-account). A field with no value is omitted.

An individual has no KYB progress. Poll `verifiedAt` after they [verify their identity](/whitelabel/sign-in-with-hevn#verify-an-individual).

Which routes take `X-Hevn-Account` is covered in [Acting as a client](/whitelabel/authentication#acting-as-a-client). For who signs a client's payouts, see [Who can spend](/whitelabel/overview#who-can-spend).

## Statuses

| `status` | Meaning | Next |
| --- | --- | --- |
| `provisioning` | The smart wallet is not deployed yet. | Poll `GET /dapi/v1/client` every 2 s. |
| `ready` | The account, your seat on it, the KYB subject and the Base smart wallet exist. | [Write the KYB document](#write-the-document). |
| `failed` | Provisioning was refused. | Contact support with the client id. |

A client is usually `ready` when you exchange the code. `poll_until` is defined in [HTTP client](/whitelabel/reference/client).

<CodeGroup>

```bash cURL
curl "$HEVN_API/client" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: cl_7YQ2Kf3mN8"
```

```python Python
client = hevn.acting_as(client_id)
ready = poll_until(
    lambda: client.get("/client"),
    lambda c: c["status"] != "provisioning",
)
```

```javascript Node
const client = hevn.actingAs(clientId);
const ready = await pollUntil(
  () => client.get("/client"),
  (c) => c.status !== "provisioning",
);
```

```go Go
client := api.ActingAs(clientID)
ready, err := hevn.PollUntil(func() (hevn.Payload, error) {
	return client.Get("/client")
}, func(c hevn.Payload) bool { return c.Str("status") != "provisioning" }, 2*time.Minute)
```

</CodeGroup>

## List clients

`GET /dapi/v1/clients` lists the accounts linked to you. Use it to recover a lost id. Filters are on [List clients](/api-reference/accounts/list-clients), and paging follows [Pagination](/whitelabel/conventions#pagination).

<CodeGroup>

```bash cURL
curl "$HEVN_API/clients?status=ready" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN"
```

```python Python
mine = hevn.get("/clients", {"status": "ready"})["items"]
```

```javascript Node
const { items: mine } = await hevn.get("/clients", { status: "ready" });
```

```go Go
page, err := api.Get("/clients", hevn.Query{"status": "ready"})
mine := page.List("items")
```

</CodeGroup>

## Update phone and address

`PATCH /dapi/v1/client` writes the phone and the postal address. The fields are on [Update a client profile](/api-reference/accounts/update-a-client-profile).

<CodeGroup>

```bash cURL
curl -X PATCH "$HEVN_API/client" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: cl_7YQ2Kf3mN8" \
  -H "Content-Type: application/json" \
  -d '{"phone":"+13125550142"}'
```

```python Python
patched = hevn.acting_as(client_id).patch("/client", {"phone": "+13125550142"})
```

```javascript Node
const patched = await hevn.actingAs(clientId).patch("/client", { phone: "+13125550142" });
```

```go Go
patched, err := api.ActingAs(clientID).Patch("/client", hevn.Body{"phone": "+13125550142"})
```

</CodeGroup>

Changing a locked field returns `409 profile_locked` with `details.fields`.

### Phone numbers

A company's virtual account requires a phone number. Either phone satisfies the check: `company.phone` in the KYB document, or the account phone written with `PATCH /dapi/v1/client`.

## Write the document

A business client is verified from one KYB document that you write, submit for review and correct on request. Write it with `PUT /dapi/v1/client/kyb` until the response returns `ready: true`. Then call `POST /dapi/v1/client/kyb/complete`.

The KYB and document routes are client-scoped, so send `X-Hevn-Account`. An individual client verifies in the [sign-in window](/whitelabel/sign-in-with-hevn#verify-an-individual).

The document has the sections `company`, `people[]` and `documents[]`. Field types, enum values and slot names are on [Provide applicant information](/api-reference/verification/provide-applicant-information).

<Steps>

<Step title="Write the company">

The example has the required fields. `company.legalName` must be unique across HEVN. A US `taxId` in a format other than `XX-XXXXXXX` counts as missing.

Also send the optional fields you hold, such as `identityDocuments`, `operatingCountries`, `highRiskActivities`, `hasPep`, `isRegulated` and the per-method volume split. Optional fields are not listed in `missing[]`, but a reviewer often asks for them in an RFI.

```json
{
  "company": {
    "legalName": "Northwind Trading Ltd",
    "country": "US",
    "taxId": "88-1234567",
    "phone": "+13125550142",
    "email": "compliance@northwind.example",
    "address": {
      "streetAddress": "401 N Michigan Ave",
      "city": "Chicago",
      "state": "US-IL",
      "zip": "60601",
      "country": "US"
    },
    "entityType": "llc",
    "expectedMonthlyVolumeUsd": "250000",
    "businessDescription": "Wholesale and retail distribution of industrial fasteners.",
    "businessType": "retail",
    "sourceOfFunds": "business_revenue",
    "purposeOfFunds": "vendor_payments",
    "flowOfFunds": "Customers pay us by wire; we pay suppliers in EUR."
  }
}
```

<CodeGroup>

```bash cURL
curl -X PUT "$HEVN_API/client/kyb" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
  -H "Content-Type: application/json" \
  --data @document.json
```

```python Python
client = hevn.acting_as(CLIENT_ID)
readiness = client.put("/client/kyb", document)
```

```javascript Node
const client = hevn.actingAs(clientId);
const readiness = await client.put("/client/kyb", document);
```

```go Go
client := api.ActingAs(clientID)
readiness, err := client.Put("/client/kyb", document)
```

</CodeGroup>

```json Response 200
{
  "ready": false,
  "missing": ["people", "documents.certificate_of_incorporation", "…"],
  "people": []
}
```

`ready: false` means the write succeeded. Read each `missing[]` entry as described in [Missing paths](#missing-paths).

</Step>

<Step title="Add the people">

`people[]` lists the client's owners, directors and signers. Give each person a stable `key` and at least one role: `ownershipPercentage`, `hasControl`, `isDirector` or `isSigner`.

```json
{
  "people": [
    {
      "key": "jane",
      "firstName": "Jane",
      "lastName": "Doe",
      "dateOfBirth": "1984-02-11",
      "email": "jane@northwind.example",
      "phone": "+13125550188",
      "address": {
        "streetAddress": "1120 W Fulton Market",
        "city": "Chicago",
        "state": "US-IL",
        "zip": "60607",
        "country": "US"
      },
      "taxIdCountry": "US",
      "taxId": "123-45-6789",
      "ownershipPercentage": "100",
      "hasControl": true,
      "isDirector": true,
      "isSigner": true
    }
  ]
}
```

```json Response 200
{
  "ready": false,
  "missing": ["people[0].documents.proof_of_address", "…"],
  "people": [{ "key": "jane", "id": "7f1e6b2c-90a4-4d31-9b5e-2c08d7a41f63" }]
}
```

Sending `people` replaces the roster you created, so a person you omit is removed. `"people": []` removes them all. For a holding company in the chain, see [Complex ownership](#complex-ownership).

</Step>

<Step title="Upload the files">

Upload each file with `POST /dapi/v1/documents`, base64-encoded in `content`, with the target slot in `slot`.

<CodeGroup>

```bash cURL
curl -X POST "$HEVN_API/documents" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
  -H "Content-Type: application/json" \
  -d "{\"slot\":\"certificate_of_incorporation\",\"fileName\":\"incorporation.pdf\",
       \"content\":\"$(base64 < incorporation.pdf | tr -d '\n')\"}"
```

```python Python
import base64, pathlib

upload = client.post("/documents", {
    "slot": "certificate_of_incorporation",
    "fileName": "incorporation.pdf",
    "content": base64.b64encode(pathlib.Path("incorporation.pdf").read_bytes()).decode(),
})
```

```javascript Node
const upload = await client.post("/documents", {
  slot: "certificate_of_incorporation",
  fileName: "incorporation.pdf",
  content: readFileSync("incorporation.pdf").toString("base64"),
});
```

```go Go
file, err := os.ReadFile("incorporation.pdf")
upload, err := client.Post("/documents", hevn.Body{
	"slot":     "certificate_of_incorporation",
	"fileName": "incorporation.pdf",
	"content":  base64.StdEncoding.EncodeToString(file),
})
```

</CodeGroup>

Responses and limits are on [Upload a document](/api-reference/documents/upload-a-document). File each returned `id` into a slot on the next `PUT`. Company files go in the top-level `documents[]` and a person's files in that person's `documents[]`.

```json
{
  "documents": [{ "slot": "certificate_of_incorporation", "uploadId": "doc_1a7Kd2" }],
  "people": [
    { "key": "jane", "documents": [{ "slot": "proof_of_address", "uploadId": "doc_5b3Qm9" }] }
  ]
}
```

An unknown slot returns `422 document_type_unsupported` with `details.field`. An `uploadId` of another client returns `404 document_not_found` with `details.uploadId`.

Required slots:

| Slot | Required when | Content |
| --- | --- | --- |
| `certificate_of_incorporation` | Always | Registrar's proof that the company exists. |
| `corporate_structure` | Always | Ownership chart, down to natural persons. |
| `director_structure` | Always | List of directors. |
| `proof_of_address` | Always | Recent document showing the registered address. |
| `source_of_funds` | Always | Evidence for the `sourceOfFunds` value. |
| `tax_identification_document` | `company.country` is `US` | IRS letter that assigned the EIN. |
| `vat_registration` | `company.country` is `AE` | FTA VAT/TRN registration certificate. |
| `regulatory_license` | `company.isRegulated` is `true` | The licence the company holds from its regulator. |
| `proof_of_address` in `people[].documents` | For each person | Recent document showing where the person lives. |

A reviewer can request any other slot in an RFI.

</Step>

</CodeGroup>

</Step>

### Missing paths

Each `missing[]` entry is a path into the document. Set the value at that path and write again.

| Path | Meaning |
| --- | --- |
| `company.flowOfFunds` | A company field is empty. |
| `company.address.zip` | A required address field is empty. |
| `people` | The roster is empty. Add at least one person. |
| `people[0].taxIdCountry` | A field on the first person is empty. |
| `people[0].documents.proof_of_address` | That person's slot is empty. |
| `documents.certificate_of_incorporation` | A company slot is empty. |
| `graph.entities.<uuid>.phone` | A field is empty on an entity reached through a holding company. See [Complex ownership](#complex-ownership). |

The index in `people[0]` is the position in `document.people[]` of `GET /dapi/v1/client/kyb`. It can differ from the order you sent.

### Complex ownership

The flat document describes one company held by people. Set `company.hasIntermediateEntityOwnership` to `true` when a holding company stands in the chain.

Write such a chain through HEVN's entity-graph routes. They are outside this API and available on request.

A flat write leaves entities added through those routes in place. A write that would remove one returns `409 kyb_roster_conflict` with `details.entityIds`.

## Track the application

`GET /dapi/v1/client/kyb` returns readiness, the application if one is filed, and the stored document. Poll it as described in [polling](/whitelabel/conventions#status-codes).

```json
{
  "ready": true,
  "missing": [],
  "status": "rfi",
  "application": {
    "id": "kyb_9F4tRb",
    "attemptNo": 1,
    "status": "rfi",
    "comment": "The proof of address for Jane Doe is older than three months.",
    "submittedAt": "2026-09-17T10:31:04Z"
  },
  "document": {
    "company": { "legalName": "Northwind Trading Ltd", "country": "US", "…": "…" },
    "people": [{ "key": "jane", "id": "7f1e6b2c-…", "…": "…" }],
    "documents": [{ "slot": "certificate_of_incorporation", "uploadId": "doc_1a7Kd2" }]
  }
}
```

| `status` | Meaning | Next |
| --- | --- | --- |
| `notStarted` | No application is filed. | Complete the document, then the submission. |
| `pending` | The application is filed and under review. | Poll. Timing is set by the reviewer. |
| `approved` | The application was accepted. | [Request virtual accounts](/whitelabel/virtual-accounts). |
| `rfi` | The reviewer asked for something. | [Answer the RFI](#answer-an-rfi). |
| `rejected` | The application was refused. | Read `application.comment`. Complete again only after you change the document. |

In the sandbox, set the status with [`POST /dapi/v1/sandbox/kyb/status`](/whitelabel/sandbox#decide-a-kyb-application).

## Answer an RFI

1. Read `application.comment`.
2. Correct the document with `PUT /dapi/v1/client/kyb`. To replace a file, file a new upload into the same slot. To correct a person, send that person's `key` and the new value.
3. Call `POST /dapi/v1/client/kyb/complete` again. `attemptNo` increments, `kybStatus` returns to `pending`, and the next review replaces `comment`.

When the reviewer could not read a value on a file, `comment` names the file and the value. Upload a legible copy, or write the value onto the upload.

### Fill a document's fields by hand

Call `PUT /dapi/v1/documents/{documentId}/content` with the upload id from the `document` block of `GET /dapi/v1/client/kyb`. Company uploads are in `documents[]` and a person's are in `people[].documents[]`.

<CodeGroup>

```bash cURL
curl -X PUT "$HEVN_API/documents/doc_1a7Kd2/content" \
  -H "Authorization: Bearer $HEVN_ACCESS_TOKEN" \
  -H "X-Hevn-Account: $HEVN_CLIENT_ID" \
  -H "Content-Type: application/json" \
  -d '{"fields":{"entity_name":"Northwind Trading Ltd","registration_number":"7712043",
       "jurisdiction":"US","incorporation_date":"2019-04-02"}}'
```

```python Python
filled = client.put("/documents/doc_1a7Kd2/content", {"fields": {
    "entity_name": "Northwind Trading Ltd", "registration_number": "7712043",
    "jurisdiction": "US", "incorporation_date": "2019-04-02",
}})
```

```javascript Node
const filled = await client.put("/documents/doc_1a7Kd2/content", { fields: {
  entity_name: "Northwind Trading Ltd", registration_number: "7712043",
  jurisdiction: "US", incorporation_date: "2019-04-02",
} });
```

```go Go
filled, err := client.Put("/documents/doc_1a7Kd2/content", hevn.Body{"fields": hevn.Body{
	"entity_name": "Northwind Trading Ltd", "registration_number": "7712043",
	"jurisdiction": "US", "incorporation_date": "2019-04-02",
}})
```

</CodeGroup>

Key format and refusals are on [Fill the typed fields read off a document](/api-reference/documents/fill-the-typed-fields-read-off-a-document).
